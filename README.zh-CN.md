# ChatPDF for Zotero

[English](README.md)

ChatPDF 是一款支持 Zotero 7–10 的插件，让你可以通过兼容 OpenAI 接口的大语言模型阅读和讨论研究论文。它在 Zotero 中提供常驻聊天面板，默认按需将页面转录为 Markdown 并缓存，保留原图仔细复查能力；PDF 提取文字用于检索和定位。

![Zotero 中的 ChatPDF 侧边面板](docs/images/chatpdf-zotero-panel.png)

## 项目定位

ChatPDF 主要为个人使用而开发，并按当前状态分享。由于 Zotero 版本、操作系统、模型服务商、网络/代理设置和个人研究工作流各不相同，本插件可能无法在所有环境中做到完美兼容。

项目源码可供调整。你可以使用 AI coding agents 协助检查错误，并针对自己的环境和工作流微调 ChatPDF，例如适配模型服务、界面行为、页面阅读方式或自定义工具。建议用版本控制保存修改、提前备份缓存，并先在隔离的 Zotero profile 中测试，再用于日常文库。

## Agent 能力更新

插件使用“文本定位 → 按页转录与缓存 → 原图仔细复查”的流程。辅助模型默认使用当前聊天模型并关闭思考，也可单独选择已保存的视觉模型配置。转换只处理请求的页面，图片不进入主对话；文字搜索仍报告检查范围和续查游标。

文库搜索、标注、笔记以及有权限控制和撤销记录的批量编辑保持可用。详见 [Agent 能力](docs/agent-capabilities.md)。

## 主要功能

- 不离开 Zotero，即可与一篇或多篇 PDF 对话。
- 在对话中搜索 Zotero 文库或记得的标注内容，并添加相关论文。
- 本地提取 PDF 文本用于搜索和定位，按需阅读原始页面中的正文、公式、图和表。
- 流式显示 Markdown、LaTeX、推理过程、工具活动和 token 用量。
- 每个 Zotero 窗口拥有独立的会话、来源列表和后台任务。
- 可选的公共网页搜索与正文抓取。
- 本地缓存提取文本、页面图片和聊天历史。
- 向本地客户端提供当前 Zotero 选择和插件能力信息。

## 使用要求

- Zotero 7、8、9 或 10.0。
- 支持 OpenAI 兼容接口和工具调用的聊天模型。查看原始页面还需支持图片输入；缺少视觉能力声明不会阻止聊天。
- 兼容 OpenAI Chat Completions 接口的模型服务 API Key。

## 安装

1. 从 [GitHub Releases](https://github.com/ruijie-xi/zotero-chat-pdf/releases) 下载 `chat-pdf.xpi`。
2. 在 Zotero 中打开 **工具 → 插件**。
3. 打开齿轮菜单，选择 **从文件安装插件…**。
4. 选择下载的 XPI，然后重启 Zotero。

首次安装仍需使用 XPI 文件。从下一个版本开始，Zotero 可通过 **工具 → 插件 → 齿轮 → 检查更新…** 发现后续 ChatPDF 版本；启用插件自动更新后也可自动安装。设置和聊天历史会继续保存在配置的缓存目录中。

## 配置

Windows/Linux 打开 **编辑 → 设置 → ChatPDF**；macOS 打开 **Zotero → 设置 → ChatPDF**。

至少需要配置：

| 设置 | 说明 |
| --- | --- |
| LLM Provider | DeepSeek、OpenCode Go 或 Custom（原有的 OpenAI 兼容配置）。 |
| LLM API Base URL | 兼容 OpenAI 接口的服务基础地址。 |
| LLM API Key | 模型服务的 Bearer Token。 |
| Model Name | 模型服务接受的模型标识。 |

默认 API 地址和模型指向 DeepSeek；已有设置和模型配置继续按 **Custom（自定义）** 加载。选择内置 provider 会填入对应地址和默认模型，provider 随模型配置一同保存。设置页面打开期间，各 provider 保留独立草稿，首次切换到另一服务时不会沿用原服务的密钥和 token 覆盖值。保存模型配置可在重启后继续使用。通过 **LLM API Test** 可检查当前接口和凭据。

**OpenCode Go** 使用 `https://opencode.ai/zen/go/v1` 和 Go API Key。建议的 DeepSeek 模型包括 `deepseek-v4.1-flash`、`deepseek-v4-pro` 和 `deepseek-v4-flash`，不加 `opencode-go/` 前缀。主对话、压缩和标题请求都会发送 ChatPDF 客户端标识及稳定的会话头；本地 token 计数使用显式的 DeepSeek V4 估算模式。已知 Go DeepSeek 型号在 `/models` 缺少容量时使用内置目录预设，接口元数据和手动覆盖优先；未知型号需要填写容量。[Go 面向编程 Agent](https://opencode.ai/docs/go/#where-can-i-use-it)，接入不代表服务方保证接受论文阅读用途。

其他可选设置包括思考控制、Agent 迭代次数、上下文与输出预算、每张图片的 token 预留、缓存目录、系统提示词、调试日志和网络工具。文本检索使用本地 PDF.js 或 Zotero 索引，不需要 OCR API key。

PDF 转录默认跟随当前聊天模型，也可在“PDF 转录模型”中选择单独的视觉模型配置；思考只在转录请求中关闭。无需确认视觉能力即可使用已启用的工具。只有接口明确拒绝图片输入时，当前原生会话中的该模型才会自动改用文字，并显示提示。当前字段即时生效。在已加载的配置中替换或清空 API key，会同步更新该配置，切换回来不会恢复旧 key；具名配置的其他修改和系统提示词仍需保存。

历史页可按聊天或论文标题搜索、置顶和筛选空会话，每次显示 50 条并可继续加载。旧会话的转换状态会迁移为直接阅读。

## 快速开始

1. 右键 Zotero 条目并选择 **Add to ChatPDF**，或把条目/阅读器标签拖入面板。
2. 配置聊天模型后，加入的 PDF 即可按需转录阅读，文字用于搜索和定位。
3. 输入问题并发送。助手会先搜索文本定位，再读取缓存 Markdown，并按需查看原图复查，并可从 Zotero 文库添加相关论文。

快捷键：

- **Enter**：发送。
- **Shift+Enter**：换行。
- **Ctrl+Enter**：发送。
- **Ctrl+F**（macOS：**Cmd+F**）：焦点在 ChatPDF 面板内时，查找当前会话中的用户消息和助手正文；也可点击顶部“查找”。在查找框中按 **Enter / Shift+Enter** 跳转到下一个／上一个匹配，按 **Esc** 关闭。思考过程、工具参数和工具结果即使已展开，也不参与匹配。

在输入框中 mention 一个或多个来源，可把当前问题限制在这些论文中；不 mention 时，助手可以使用当前会话的全部来源。使用 **Stop** 可以取消回答和正在进行的页面读取。

## PDF 阅读与搜索

普通阅读使用 `read_pdf_page`：已有页缓存直接返回，缺失页由辅助模型独立转换；默认批量读取 4 页，支持指定页码列表。成功页单独保存，某页失败不会丢掉其他页。切换聊天模型不会使缓存失效，`refresh=true` 可显式重转指定页。`inspect_pdf_page` 保留原图复查：整页默认 200 DPI，局部默认 600 DPI，返回原 PDF 页码引用。关键公式、准确数值、图形和转录疑点应对照原图确认。原图仍使用现有图片历史管理，Markdown 不会因为旧图移出上下文而丢失。详见 [管线与缓存约定](docs/pdf-markdown-reading.md)。

长文先搜索、再查看相关页面，无需整篇预处理。Markdown、文本与页图按附件身份和文件版本缓存。当前不接入外部 OCR 引擎；请求的无文本层页面也可交给视觉辅助模型转录。没有文本层的页面仍可渲染成图片，但关键词检索会报告缺少文本，不会自动启动 OCR。[OCR 调研记录](docs/local-ocr-options.md)仅供后续参考，不是当前开发计划。

Agent 可以通过 `locate_pdf_content` 按原文片段、定理标题、公式编号或图题定位内容，获得匹配页、文字区域和引用链接。在 ChatPDF 中点击区域链接，会跳转并短暂高亮目标；已知页码时可直接定位该页，坐标缓存可跨会话复用，无需额外模型调用。公式编号的位置不代表整个公式的范围。详见 [内容定位与区域引用](docs/pdf-content-location.md)。

## 本地 MCP 集成

ChatPDF 原生 Agent 与配套 [Zotero MCP](https://github.com/ruijie-xi/zotero-mcp) 共用 Zotero 内的一套工具定义和执行逻辑。25 个工具默认全部开启，可在 **设置 → 可用工具** 中逐项关闭或开启；两端同时生效，旧连接调用已禁用工具也会被拒绝。文库修改继续遵守聊天窗口的权限和逐批确认。

MCP 通过 `POST /chatpdf/v2`（严格协议版本 2）转发工具发现、参数和文本/图片结果，不再自行读取文库数据库、转换缓存或另写搜索逻辑。`read_pdf_page` 返回按需转录并缓存的 Markdown，`inspect_pdf_page` 将 PDF 原页作为 MCP 图片内容返回。每个 MCP 会话保留独立的文献范围和结果历史，阅读前使用 `add_zotero_item_to_session` 加入文献。

插件和 MCP 必须同时使用协议 2 的匹配构建。旧 v1 桥接及旧转换/文档工具名称不再支持；外部客户端缓存了工具列表时，需要重连或重启。这不包含加载任意第三方 MCP 服务器的功能。详见 [共享工具通道](docs/shared-tools.md) 和 [项目状态](docs/project-status.md)。

## 网络工具

网页搜索和网页读取默认开启，可分别关闭。调用时，助手可以搜索公共网页，并从 HTTP(S) 页面抓取可读文本。

出于安全考虑，ChatPDF 会阻止内嵌凭据、本机和私有/链路本地网络、不安全重定向、不支持的内容类型、超时请求和过大响应。被拦截的请求会明确报错，不会返回隐藏的部分内容。

## 数据与隐私

默认缓存目录是 `~/.chatpdf-cache/`，可在设置中修改。当前缓存保存页级 Markdown、本地 PDF 文本、页面图片、独立图片来源、聊天历史和调试日志。

- 只有请求未缓存页面时，才会把页图发送给辅助模型；原图复查时才把图片发送给聊天模型。加入 PDF 或启动 Zotero 不会触发转录调用；本地文本搜索不需要 OCR 服务密钥。
- 对话消息、相关文档内容和工具结果会发送到你配置的 LLM 服务商。
- 只有启用并实际使用网络工具时，查询和目标网页才会发送到搜索服务和对应网站。
- 调试日志默认只记录元数据；**Full** 模式可能包含提示词、论文正文、回答、推理和工具结果。
- API Key 保存在 Zotero 首选项中，请勿把它们放入截图或错误报告。

## 故障排查

**面板没有出现：**确认已在 **工具 → 插件** 中启用 ChatPDF，然后重启 Zotero。

**模型请求失败：**运行 **LLM API Test**，检查基础地址、Key、模型名称以及服务兼容性。

**无法读取页面：**检查 PDF 是否已下载、是否加密，以及上下文容量和每张图片的 token 预留。缺少视觉能力声明不会阻止调用；接口明确拒绝图片时会自动继续读取文字，并说明依据。认证失败、网络故障、图片大小和解码问题仍会正常报错。请求成功本身不能证明中间服务确实转交了图片。

**无法读取来源：**确认 PDF 已下载到本地，并包含在当前问题 mention 的范围或当前会话中。使用支持图片输入的聊天模型。

**网页搜索或抓取失败：**确认已启用网络工具。本机/私网目标和不安全响应会被有意拦截。
