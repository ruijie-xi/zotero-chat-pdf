## Current design

- ChatPDF is a Zotero 7-10 plugin. The current release scope is v0.10.1. Runtime acceptance used Zotero 10.0.6; this does not certify every supported version.
- On-demand page Markdown transcription is implemented; see [Page transcription](pdf-markdown-reading.md). The current chat model is the default helper, thinking is disabled, and a separate saved visual profile can be selected. Legacy whole-document/MinerU/self-check jobs remain retired; their caches and credentials are not deleted.
- Ordinary reading uses read_pdf_page Markdown with independent page caches and two shared conversion workers. inspect_pdf_page retains ordered image batches (four full pages at 200 DPI by default), 600 DPI region crops, exact citations and explicit raster/image limits. Key formulas, figures, table values and uncertain transcription can be checked against original images. Cached Markdown never claims scientific verification.
- Only an explicit HTTP 400/415/422 image-input rejection activates text fallback. Original events and completed tool receipts remain intact; outgoing images are removed and image tools are temporarily unavailable for that live native session and endpoint/model/account. A visible notice identifies the evidence limitation. Cancellation, authentication, rate limits, network errors and invalid images never trigger image fallback. Transient HTTP failures now use bounded transport recovery.
- Native request history uses a soft 20 MiB inline-Base64 trigger and 10 MiB target. Old images accepted in a completed provider response are replaced in batches with stable rereadable references; fresh images stay intact, even above the watermarks. Text analysis and exact tool receipts remain. HTTP 413 first forces additional old-image offload, then falls back to same-model grouped checkpoint recovery when new images or text still cannot fit. An indivisible rejected input produces an explicit error. This is not a cumulative reading quota or a hard request cap.
- External OCR engines and a dedicated scanned-document workflow remain deferred. The page transcription helper uses the configured LLM API. [OCR research](local-ocr-options.md) records PaddleOCR-VL-1.6 size, formula benchmark interpretation and hosted-service limits. No OCR dependency, download or public OCR request was added.
- Native chat and Zotero MCP use one registry, validation path and executor. All **25 tools are enabled by default**, with shared individual settings. Native text fallback does not change the global switches. See [Shared tools](shared-tools.md).

## Compatibility boundary

The companion repository is `D:\Myfiles\Codes\zotero-mcp`. It forwards standard MCP calls to `POST /chatpdf/v2`. It does not duplicate document/library searches or read conversion caches. Native chat works without that Python process.

Names, descriptions and JSON schemas come from the same registry. Results include complete Markdown through read_pdf_page and original page images through inspect_pdf_page as standard MCP image content. External sessions have independent source sets and result history. Library scope, trusted batch approval, transactions and conflict checks remain enforced in Zotero.

External MCP hosts own their model requests and recovery. The bridge cannot determine their model capability or observe their provider's image rejection; it continues to expose the enabled catalog. The native fallback cache is memory-only. Switching model/account, refreshing model settings, clearing chat or reopening a saved session permits another attempt.

Protocol 1 and the former research/connector contracts are retired. Both legacy CLI toolset names select the live catalog. A host restricted to the old two-tool search/fetch contract needs a separate integration.

## OpenCode Go diagnosis and recovery (2026-10-21)

This recovery difference explains why the same transient failure was immediately visible in ChatPDF; it does not establish the gateway's underlying routing cause or guarantee every retry will succeed.

Controlled probes with ChatPDF's own identity reproduced the error from both Windows and WSL, on both the legacy and current documented Go endpoints. No credential was displayed, copied into an isolated profile or replaced in either client's settings. No model or client identity was substituted.

ChatPDF now retries transient HTTP 408/429/500/502/503/504 at most twice (three total attempts), honoring Retry-After waits up to 30 seconds. Longer provider waits stop rather than retry early. Explicit exhausted-quota/billing codes, authentication and ordinary validation errors do not retry. Partial model streams are never replayed; completed tool operations and request contents are retained. See [transport recovery](llm-workflow.md#transient-http-recovery). ## DeepSeek Harness comparison and cache tradeoff (2026-10-21)

Read-only inspection of the installed WSL DeepSeek Harness 0.2.1-rc.2 and its active configuration identified the OpenCode Go route as `dsh-llm-pi-ai`. Its defaults include a 20 MiB inline-image budget, a 4,194,304-pixel per-image normalization target and a 1 MiB per-image encoding target. The separate direct-DeepSeek Files API route is not the user's Go path. These are implementation/configuration findings, not a live A/B comparison of identical multi-image requests; the bounded recent-session sample contained no image-offload events.

ChatPDF now follows the same one-way old-image-reference approach, with batching toward a lower target to reduce repeated prefix edits. It protects images until they have been accepted in a completed response and does not impose a 1 MiB image-compression target. It reduces full-page browsing to 200 DPI and defaults region reads to 600 DPI from the original PDF. JPEG quality remains 95; explicit caller resolution is preserved. Offloading itself never recompresses retained images.

An old-image replacement can reduce cache hits from the first changed position. Earlier stable content is only eligible for matching persisted prefix units, not guaranteed to hit. Fixed references and append-only rereads allow a stable prefix afterward; batching creates headroom before another rewrite. See [DeepSeek cache rules](https://api-docs.deepseek.com/guides/kv_cache/) and [Harness offload documentation](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/compaction/compaction-image-offload/README.md). The local tests verify exact prefix structure; real Go cache hit-rate improvement and formula recognition accuracy were not measured. Changing the tool descriptions/system prompt once may rebuild an old chat's working context after this update.
